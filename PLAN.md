# План: прошивка «Hello Denis» по USB CDC для RP2350B (PiZero)

## Контекст

Цель — самостоятельно (без участия Claude, пока явно не попросишь) написать первую прошивку для платы на RP2350B формата Pi Zero (предполагаю Waveshare RP2350-PiZero). После подключения к компьютеру плата должна появиться как виртуальный COM-порт и выводить в него строку `Hello Denis`.

Папка `c:\project\rp2350_proba` пустая, проект создаётся с нуля.

Выбранный стек (моё предположение по умолчанию): **официальный Pico SDK на C** через расширение **Raspberry Pi Pico для VS Code**. Оно само ставит SDK, компилятор, CMake, Ninja и picotool — на Windows это самый короткий путь. Если хочешь MicroPython, Rust или Arduino — план будет другим, скажи.

## Шаг 1. Окружение

1. В VS Code установить расширение **Raspberry Pi Pico** (издатель Raspberry Pi).
2. Через его панель выбрать **New C/C++ Project**:
   - расположение: `c:\project\rp2350_proba`;
   - SDK: версия 2.1.0 или новее (в более старых нет RP2350B-плат);
   - плата: искать `waveshare_rp2350_pizero` в списке. Если её нет — взять `pico2` (для этой задачи разницы нет: USB и загрузка работают одинаково, отличается только число GPIO и размер флеша);
   - архитектура: ARM (не RISC-V);
   - **Stdio support: включить «Console over USB», выключить «Console over UART»**.
3. Дождаться, пока расширение скачает тулчейн (первый раз — несколько минут).

Проверка: в папке появились `CMakeLists.txt`, `pico_sdk_import.cmake`, файл `.c` и папка `.vscode`.

## Шаг 2. CMakeLists.txt

Убедиться, что в сгенерированном файле есть (и понять, что делает каждая строка):

- `set(PICO_BOARD ...)` — выбранная плата, стоит **до** `pico_sdk_init()`;
- `pico_enable_stdio_usb(<target> 1)` — направляет `printf` в USB CDC;
- `pico_enable_stdio_uart(<target> 0)` — отключает вывод в UART;
- `target_link_libraries(<target> pico_stdlib)`;
- `pico_add_extra_outputs(<target>)` — без неё не будет файла `.uf2`.

## Шаг 3. Код (main)

Написать самому, нужны три вещи из `pico/stdlib.h`:

1. `stdio_init_all()` — поднимает USB CDC. Вызвать первой.
2. Дождаться открытия порта на компьютере: цикл с `stdio_usb_connected()` и `sleep_ms()` внутри. Без этого строка уйдёт раньше, чем ты откроешь терминал, и ты её не увидишь.
3. `printf("Hello Denis\n")`.

Рекомендация: печатать строку в бесконечном цикле раз в секунду, а не один раз — так гораздо проще отлаживать. Когда заработает, можно оставить однократный вывод после ожидания подключения.

`main` не должен завершаться — в конце нужен бесконечный цикл.

## Шаг 4. Сборка

Кнопка **Compile** в строке состояния VS Code (или «Compile Project» в панели расширения).

Проверка: в `build\` появился `<имя_проекта>.uf2`.

## Шаг 5. Прошивка

1. Зажать кнопку **BOOT** на плате и, удерживая её, подключить USB-кабель к компьютеру. Отпустить.
2. В проводнике появится диск **RP2350**.
3. Скопировать на него `.uf2`. Диск исчезнет, плата перезагрузится в твою прошивку.

Альтернатива: кнопка **Run** в расширении (заливает через picotool, плата тоже должна быть в режиме BOOT).

## Шаг 6. Проверка

1. Диспетчер устройств → «Порты (COM и LPT)» → появилось «Устройство с последовательным интерфейсом USB (COMx)».
2. Открыть порт: расширение **Serial Monitor** в VS Code или PuTTY. Скорость любая (для USB CDC она не имеет значения), например 115200.
3. В терминале должна появиться строка `Hello Denis`.

## Если не работает

| Симптом | Причина |
|---|---|
| Диск RP2350 не появляется | Кабель только для зарядки; BOOT отпущен до подключения; не тот разъём — на Waveshare PiZero два USB-C, нужен обычный **USB**, не **PIO-USB** |
| Диск есть, COM-порта после прошивки нет | В CMake не включён `pico_enable_stdio_usb`, либо не вызван `stdio_init_all()`, либо `main` завершился |
| Порт есть, в терминале пусто | Строка напечатана до открытия порта (см. шаг 3, п. 2); терминал не выставляет DTR — в PuTTY/Serial Monitor включить DTR, иначе `stdio_usb_connected()` остаётся `false` |
| `.uf2` копируется, но плата снова показывает диск | Прошивка собрана под другую платформу (RP2040 или RISC-V) — проверить плату и архитектуру в шаге 1 |
| Порт «занят» при повторной прошивке | Закрыть терминал перед заливкой |

## Критерий готовности

Плата подключена обычным способом (без BOOT), в диспетчере устройств виден COM-порт, после его открытия в терминале видна строка `Hello Denis`.

# Этап 2. USB-клавиатура на разъёме PIO-USB → символы в COM5

## Контекст

Этап 1 выполнен: плата видна как COM5 и печатает `Hello Denis`. Теперь плата работает в двух ролях одновременно:

- **устройство** (device) на обычном разъёме USB — тот же CDC-порт COM5, в него идёт `printf`;
- **хост** (host) на разъёме PIO-USB — к нему подключена клавиатура. Аппаратный USB-контроллер у RP2350 один и он занят ролью устройства, поэтому хост делается программно на PIO библиотекой **Pico-PIO-USB**, а поверх неё работает хост-стек TinyUSB с классом HID.

Эталон для подглядывания — пример из самого SDK, он делает ровно это (HID-хост на PIO-USB → вывод в CDC):
`%USERPROFILE%\.pico-sdk\sdk\2.3.1\lib\tinyusb\examples\dual\host_hid_to_device_cdc\` (`src/main.c`, `src/tusb_config.h`).
Отличие: там вывод через `tud_cdc_write`, а у нас должен остаться `printf` через `pico_stdio_usb`.

Что меняется по сравнению с этапом 1 (проверено по исходникам SDK 2.3.1):

- Pico-PIO-USB **в SDK не входит** — папки `lib/tinyusb/hw/mcu/raspberry_pi/Pico-PIO-USB` нет, библиотеку надо скачать отдельно.
- Как только к цели прилинкован `tinyusb_host`, `pico_stdio_usb` перестаёт делать три вещи сам (см. `pico/stdio_usb.h`, условия `!LIB_TINYUSB_HOST && !LIB_TINYUSB_DEVICE`): вызывать `tusb_init()`, крутить `tud_task()` в фоне по таймеру и давать готовые USB-дескрипторы. Плюс отключается сброс в BOOT по 1200 бод.
- `stdio_usb.c` вообще компилируется рядом с хостом только если определён `CFG_TUH_RPI_PIO_USB` — иначе будет предупреждение «stdio USB was configured, but is being disabled» и COM-порт пропадёт.
- В файле платы `waveshare_rp2350_pizero.h` пинов PIO-USB нет — их надо задать самому.

## Шаг 7. Железо и пины

1. Найти в схеме/вики Waveshare RP2350-PiZero, на какие GPIO выведены D+ и D− разъёма PIO-USB. Предположительно **GP28 (D+) и GP29 (D−)** — это не проверено, сверить со схемой. Библиотеке нужен номер D+, а D− должен быть соседним (D+ + 1 по умолчанию; обратный порядок задаётся отдельным полем конфигурации).
2. Выяснить, подаётся ли на разъём PIO-USB 5 В и нет ли пина включения питания (VBUS enable). Проще всего — мультиметром на переходнике или по схеме. Без 5 В клавиатура не запустится.
3. Клавиатура подключается через переходник USB-C → USB-A (OTG). Для первого запуска взять простую проводную клавиатуру без хаба, подсветки и радиодонгла.

Проверка: известны номер GPIO для D+, порядок D+/D− и то, что на разъёме есть 5 В.

## Шаг 8. Получить Pico-PIO-USB

1. Склонировать `https://github.com/sekigon-gonnoc/Pico-PIO-USB` в подпапку проекта (например `lib/Pico-PIO-USB`), лучше как git submodule — проект уже в git.
2. Версия: TinyUSB 0.18.0 из SDK закреплён на коммите `fe9133fc513b82cc3dc62c67cb51f2339cf29ef7` (см. `lib/tinyusb/tools/get_deps.py`). Начать с него; если под RP2350 не соберётся — пробовать свежий тег.
3. Прочитать в README библиотеки раздел про требования к частоте `clk_sys` и про пины.

Проверка: существует `lib/Pico-PIO-USB/src/pio_usb.c`.

## Шаг 9. CMakeLists.txt

Блок `DO NOT EDIT` не трогать, всё ниже него.

1. Задать переменную `PICO_PIO_USB_PATH` (путь к папке из шага 8) **до** `pico_sdk_init()`. Только тогда SDK создаст цель `tinyusb_pico_pio_usb` — логика в `lib/tinyusb/hw/bsp/rp2040/family.cmake`, функция `check_and_add_pico_pio_usb_support`.
2. В `target_link_libraries` добавить `tinyusb_host` и `tinyusb_pico_pio_usb`. `tinyusb_device` отдельно не нужен — стек устройства уже приходит через `pico_stdio_usb`.
3. Через `target_compile_definitions` решить судьбу трёх настроек `pico_stdio_usb`:
   - `PICO_STDIO_USB_USE_DEFAULT_DESCRIPTORS=1` — оставить готовые дескрипторы CDC, чтобы не писать свой `usb_descriptors.c`;
   - `PICO_STDIO_USB_ENABLE_TINYUSB_INIT` и `PICO_STDIO_USB_ENABLE_IRQ_BACKGROUND_TASK` оставить по умолчанию (0) — инициализацию и `tud_task()` делаешь сам в шаге 11, так понятнее, что происходит.
4. Убедиться, что папка проекта есть в `target_include_directories` (уже есть) — там будет лежать свой `tusb_config.h`.
5. Pico-PIO-USB собирается с предупреждениями; если где-то включён `-Werror`, смотреть список `-Wno-error=...` в `CMakeLists.txt` примера.

Проверка: конфигурация CMake проходит, в логе нет ошибки «target tinyusb_pico_pio_usb not found».

## Шаг 10. Свой tusb_config.h

Создать `tusb_config.h` в корне проекта. Он перекрывает одноимённый файл из `pico_stdio_usb` (тот подключён как системный include, поэтому папка проекта выигрывает). Образец — `tusb_config.h` примера. Что в нём должно быть и зачем:

- порт 0 — устройство, порт 1 — хост (`CFG_TUD_ENABLED`, `CFG_TUH_ENABLED`, номера `BOARD_TUD_RHPORT 0` / `BOARD_TUH_RHPORT 1`; драйвер PIO-USB в TinyUSB жёстко считает свой порт первым, а не нулевым);
- `CFG_TUH_RPI_PIO_USB 1` — хост работает через PIO, и это же условие оставляет `stdio_usb` включённым;
- сторона устройства: `CFG_TUD_CDC 1` и размеры буферов CDC (взять из `pico_stdio_usb/include/tusb_config.h`);
- сторона хоста: `CFG_TUH_HID`, `CFG_TUH_DEVICE_MAX`, `CFG_TUH_ENUMERATION_BUFSIZE`, размеры буферов HID; `CFG_TUH_HUB` — по желанию (нужен, если клавиатура со встроенным хабом).

`CFG_TUSB_MCU` и `CFG_TUSB_OS` определять не надо — они приходят из CMake.

Проверка: проект компилируется (пока без нового кода в `main`), предупреждения «stdio USB ... is being disabled» нет.

## Шаг 11. Инициализация в main

Порядок важен:

1. **Системная частота.** По умолчанию у RP2350 150 МГц, а PIO-USB нужна частота, из которой получается ровный делитель для USB (пример TinyUSB ставит 120 МГц — `set_sys_clock_khz` в `hw/bsp/rp2040/family.c`, функция `board_init`). Сделать это первой строкой `main`, до любой инициализации USB.
2. **Питание порта**, если в шаге 7 нашёлся пин VBUS enable.
3. **Конфигурация PIO-USB:** структура `pio_usb_configuration_t` со значением `PIO_USB_DEFAULT_CONFIG`, поменять `pin_dp` на свой и передать через `tuh_configure(...)` с идентификатором `TUH_CFGID_RPI_PIO_USB_CONFIGURATION`. Обязательно **до** инициализации хоста.
4. **Инициализация обоих стеков** через `tusb_init(порт, &структура)` — отдельно устройство на порту 0 и хост на порту 1 (как в `main` примера).
5. **`stdio_init_all()`** — после инициализации устройства: теперь он не поднимает USB сам, а только подключает `printf` к уже работающему CDC.
6. **Главный цикл** без пауз: на каждом проходе вызывать `tud_task()` и `tuh_task()`.

Главная ловушка: старый цикл `while (!stdio_usb_connected()) sleep_ms(100);` больше не сработает — фоновой задачи нет, и без вызова `tud_task()` внутри цикла порт никогда не «подключится». Ожидание терминала надо переделать: либо крутить `tud_task()`/`tuh_task()` и в цикле ожидания, либо завести флаг «приветствие уже напечатано» и проверять его в общем цикле. Любой `sleep_ms` в главном цикле тормозит оба стека.

Проверка (промежуточная, без клавиатуры): после прошивки COM-порт на месте, при открытии терминала по-прежнему печатается `Hello Denis`. Пока это не работает — к клавиатуре не переходить.

## Шаг 12. Обнаружение клавиатуры

TinyUSB сам вызывает функции с фиксированными именами — их нужно просто определить у себя:

- `tuh_hid_mount_cb` — подключено HID-устройство. Напечатать через `printf` VID/PID (`tuh_vid_pid_get`) и протокол интерфейса (`tuh_hid_interface_protocol`; клавиатура — `HID_ITF_PROTOCOL_KEYBOARD`). Здесь же запросить первый отчёт: `tuh_hid_receive_report`.
- `tuh_hid_umount_cb` — устройство отключено, напечатать сообщение.

Проверка: при втыкании клавиатуры в COM5 появляется строка с VID/PID и «Keyboard», при вытаскивании — сообщение об отключении. Это отдельная контрольная точка: она показывает, что работают питание, пины, частота и перечисление устройства.

## Шаг 13. От отчёта к символу

1. Определить `tuh_hid_report_received_cb`. Для клавиатуры отчёт — структура `hid_keyboard_report_t`: байт модификаторов (Shift, Ctrl…) и массив из 6 кодов одновременно нажатых клавиш.
2. В конце обработчика **снова** вызвать `tuh_hid_receive_report` — иначе придёт ровно один отчёт и всё замолчит.
3. Отчёт приходит и при нажатии, и при отпускании, а удерживаемая клавиша остаётся в массиве. Чтобы печатать символ один раз, хранить предыдущий отчёт и считать нажатием только код, которого в предыдущем не было.
4. Код клавиши — это не ASCII, а номер клавиши по таблице HID Usage. Для перевода в TinyUSB есть готовая таблица `HID_KEYCODE_TO_ASCII` (`class/hid/hid.h`): два столбца — без Shift и с Shift. Раскладка ПК тут ни при чём, таблица даёт US-раскладку.
5. Напечатать символ через `printf`/`putchar`. Учесть, что stdout буферизуется построчно: одиночный символ без `\n` может не появиться сразу — посмотреть в сторону `fflush(stdout)` или `stdio_flush()`.

Сначала можно печатать сырые коды (`%02x`) — так видно, что отчёты идут, а потом добавить перевод в символы.

## Шаг 14. Сборка, прошивка, проверка

1. Закрыть терминал, **Compile**, прошить через BOOT как раньше (сброс по 1200 бод теперь отключён, кнопка **Run** без BOOT не сработает).
2. Плата — обычным разъёмом USB к ПК, клавиатура — в PIO-USB.
3. Открыть COM5 с включённым DTR. Номер порта мог измениться — состав USB-интерфейсов платы стал другим; проверить в диспетчере устройств.
4. Нажимать клавиши на USB-клавиатуре — символы появляются в терминале.

| Работает с одной клавиатурой, не работает с другой | Клавиатура с встроенным хабом (нужен `CFG_TUH_HUB`) или составная — начать с простой |

## Критерий готовности (этап 2)

Плата подключена к ПК обычным разъёмом USB, клавиатура — к PIO-USB. После открытия COM5 печатается `Hello Denis`, затем каждая нажатая на USB-клавиатуре буквенно-цифровая клавиша даёт ровно один символ в терминале, с учётом Shift.
